# 用户 CLI 交接

## 原则

本 skill 不知道用户采用哪一种 Seedance 视频生成 CLI，也不携带任何 CLI 实现。不要创建 runner、shell/batch/PowerShell 包装器、SDK 调用、provider 配置、依赖清单或示例命令。只接受并执行用户在当前对话中明确提供的单条完整 CLI 调用。

## 询问文本

在剧本、资产、Seedance 提示词和制作包校验完成后，向用户发出一个阻塞式问题：

> 请把你准备使用的完整视频生成 CLI 命令粘贴过来。我会在 `<project_dir>` 中按原命令执行。不要把 API key、token 或密码直接写进命令，请先放进本地环境变量；如果你想自己运行，请回复“我自己运行”。

不要猜测可执行文件名、子命令、模型、参数、账号、endpoint 或上传语法。不要把提示词自动拼进未知 CLI 参数。

## 收到命令后

1. 把整段输入视为用户提供的命令，不改写参数、不插入密钥、不增加联网、付费或发布选项。
2. 只接受单个可执行程序及其参数；出现额外 shell 语句、命令串联、管道、重定向或脚本块时，要求用户改成单条 CLI 调用。
3. 检查命令是否包含明文凭据、递归删除、磁盘格式化、覆盖项目外文件或其他明显越界操作。
4. 明文凭据存在时不执行，要求用户撤销该凭据并改用环境变量。
5. 破坏性或项目外写入操作存在时不执行，指出具体片段并要求安全版本或明确的新授权。
6. 可执行文件不存在或命令缺少必填参数时，如实返回错误，让用户提供修正版；不要替用户猜测。
7. 安全且范围明确时，从 `project_dir` 直接执行用户原命令。需要交互输入时保留 TTY，把 CLI 自己的问题交给用户回答。
8. 不把命令保存进 skill。若记录项目回执，只保存已脱敏的可执行文件名、执行时间、退出码和输出路径，不记录参数中的秘密。

## 验收

执行结束后检查：

- 退出码为 0，或 CLI 明确报告任务成功。
- 目标视频文件真实存在、大小大于 0、能被媒体探测工具读取。
- 视频路径位于项目目录或用户明确指定的位置。
- 若是异步任务，只报告 task/job ID 和当前状态；不得把“已提交”写成“已生成”。
- 若 CLI 只返回远端 URL，报告 URL，但不要虚构本地文件。

把脱敏后的结果写入 `production/video-run.md`。若用户自己运行，在该文件中标记“由用户自行执行，Codex 未运行”。

# Canvas AGENT 第一阶段实施计划

依据：`docs/superpowers/specs/2026-08-20-canvas-agent-delivery-foundation-design.md`

## 实施边界

- 新能力放在独立的 `canvasAgentFoundation` 服务目录中，通过小型路由适配器接入现有画布。
- 不修改一键复色的素材、设置、任务或 API。
- 不重写现有 `smart-canvas-core.js`、`agentRunService.js` 或 `agentScriptVersionService.js`。
- 不调用任何外部或付费模型。

## Task 1.1：精确备份与代码基线

1. 记录 Git 状态、关键文件哈希、现有自动化测试结果和画布数据哈希。
2. 备份本阶段将修改的文件和关键画布数据到独立恢复目录。
3. 生成机器可读清单，确保可验证、可回滚且不包含一键复色数据迁移。

## Task 1.2：统一产物版本结构

1. 实现不可变 Artifact Version Store、内容哈希和元数据校验。
2. 用 `operationId` 保证重复请求幂等。
3. 拒绝覆盖成功版本、缺失内容和哈希不一致。

## Task 1.3：依赖关系图

1. 实现正向依赖、反向依赖、持久化和循环检测。
2. 只保存版本 ID 关系，不复制或删除产物文件。

## Task 1.4：影响传播

1. 从被替换版本沿反向依赖精确传播。
2. 直接受影响标记 `stale`，间接受影响标记 `needs-review`。
3. 支持人工确认复用和重新绑定，并写入审计记录。

## Task 1.5：审核关卡引擎

1. 实现 `draft → awaiting-review → approved → locked` 合法状态机。
2. 新版本锁定后旧版本保留并变为 `superseded`。
3. 审核状态与有效性状态独立保存。

## Task 1.6：付费步骤安全门

1. 校验全部输入必须为 `locked + current`。
2. 精确授权绑定 Provider、模型、输入版本、数量、预算和操作 ID。
3. 任一参数变化、预算不足或授权缺失时阻断执行。

## Task 1.7：统一任务账本

1. 创建 `docs/canvas-agent/execution-ledger.json`、决定日志、阶段映射和恢复协议。
2. 实现账本校验、原子写入、证据登记和唯一 `nextAction`。
3. 将旧 16 阶段历史映射到新 10 阶段，不抹除已有成果。

## Task 1.8：恢复审计与画布投影

1. 实现 Recovery Auditor，对账 Artifact、依赖、Run、账本和画布投影。
2. 运行中操作重启后变为 `interrupted`，绝不自动重发付费请求。
3. 提供只读状态 API 与画布投影数据，使刷新后节点能从后端事实重建。

## 测试顺序

1. 先新增第一阶段单元/集成测试，覆盖版本、依赖、传播、审核、安全门、账本和恢复。
2. 运行现有画布 AGENT 的 23 项阶段 2 测试。
3. 运行画布往返测试，比较生产画布数据前后哈希。
4. 启动本地服务，验证状态 API 和刷新恢复。
5. 发现问题立即修复并重跑全部相关测试；全部通过后把账本停在阶段 1 用户审核。

## 完成输出

- 1.1–1.8 每项状态与证据。
- 修改文件、未修改范围、备份位置、测试结果和已知限制。
- 阶段 1 只标记 `awaiting-user`，不会自动进入下一阶段。

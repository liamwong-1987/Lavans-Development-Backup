# 一键复色「重做」按钮无法真实重新生成 — 修复报告

- 日期：2026-08-17
- 范围：`resources/backend/server.js` + `resources/frontend/app.js`

## 一、现象

任务列表里点「重做」按钮，任务只是变成 pending 状态，但**没有真正调用 API 重新生成图片**，一直卡着不出图。

## 二、根因

`/api/batches/:batchId/retry-task` 接口（server.js L535）只做了两件事：

1. 把目标任务重置为 `pending`
2. `batchStore.saveBatch(batch)` 保存后返回

**但它漏了两个关键动作：**

1. **没有恢复批次运行状态** —— 批次之前可能是 `completed`/`active=false`，重置单个任务后批次状态没变，runner 不会处理这个 pending 任务。
2. **没有启动 runner** —— 接口虽然接收了 `skipStart` 参数，但完全没使用；重置后没有任何代码触发 `taskRunner.start()`，所以任务永远不会被执行。

对比同文件里能正常工作的 `/api/batches/:batchId/resume` 接口：它调用了 `batchService.resumeBatchTasks(batch)`（会设置 `batch.status='running'`、`batch.active=true`、`batch.cancelRequested=false`）然后 `taskRunner.start(batch.batchId)`。retry-task 缺的就是这两步。

## 三、修复

### 后端 server.js（retry-task 接口）

在重置任务后，新增：

1. 恢复批次状态：`batch.status='running'; batch.active=true; batch.cancelRequested=false;`
2. `skipStart` 为 false 时启动 runner：`taskRunner.start(batch.batchId)`

### 前端 app.js（retrySingleTask）

- retry 成功后调用 `startPolling(true)`，启动轮询实时更新生成进度（之前只 refresh 一次，看不到进度）
- toast 文案从「已加入生成队列」改为「已开始重新生成」

## 四、验证

- `node --check` server.js / app.js 均通过（Exit 0）。
- 修复逻辑与 resume 接口对齐，复用现有 `taskRunner.start` 机制，不新增生成逻辑。

## 五、文件清单

- `resources/backend/server.js`（+10 行）
- `resources/frontend/app.js`（+2/-1 行）

## 六、注意

需**重启 Lavans** 后生效。重启后点「重做」，任务会真正进入生成流程并出图。

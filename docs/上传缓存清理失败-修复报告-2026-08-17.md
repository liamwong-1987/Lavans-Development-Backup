## 一、问题现象

复色模块上传素材时，界面报「**清理上传缓存失败**」，导致无法上传新模板/颜色图。

## 二、根因

上传接口 `/api/upload`（`routes/scanRoutes.js`）在非追加模式下，先调 `fileStore.clearUploads(type)` 清理旧文件再上传。

`clearUploads()` 函数用**裸 `fs.unlinkSync(p)`** 删除旧文件，遇到 Windows 文件占用/锁定就抛异常 → `failed` 非空 → 返回 `success: false` → 接口返回「清理上传缓存失败」。

而同一文件里更健壮的 `clearAllUploads()` / `clearDirectoryContents()` 早已使用 `removePathWithRetry()`（内部走 PowerShell 原生删除 + 4 次重试 + chmod 兜底），能抗文件占用。**唯独 `clearUploads` 漏改，仍在用脆弱的 unlinkSync。**

### 触发证据
- `resources/uploads/colors/` 残留 00:13 的旧文件 `43.jpg`、`44.jpg`；04:23 上传新颜色时清理失败。

## 三、修复内容

文件 `D:\Lavans备份\resources\backend\fileStore.js`，`clearUploads()` 函数内（L240-242）：

**改前**（裸删除）：
```js
try {
  if (e.isFile()) fs.unlinkSync(p);
  else if (e.isDirectory() && !normalized) fs.rmSync(p, { recursive: true, force: true });
} catch (error) {
  failed.push({ path: p, reason: error.code || error.message });
}
```

**改后**（复用健壮的 removePathWithRetry）：
```js
const result = removePathWithRetry(p);
if (result !== true) failed.push({ path: p, reason: result.code || result.message });
```

保持不变的逻辑：`normalized` 白名单校验、`root`/`dir` 计算、`activeUploadSessionId` 清理、返回结构 `{ success, failed }`。

# 视频时长滑块 3 Bug 修复报告

- 日期：2026-08-18
- 提交：`121adf4`
- 范围：视频生成节点「时长」滑块功能

## 背景

上一轮把视频时长选择从「按钮 + 自定义输入」改为「拖动滑块」，并在 `canvas-config.json` 写入 7 个模型的官方时长范围。复查发现 3 个 bug，其中 1 个致命（功能完全失效）。

## 3 个 Bug 与修复

### Bug #1（致命）：后端白名单漏 `video_model_durations`

- **文件**：`resources/backend/moduleConfigService.js`
- **根因**：`normalizeProvider()` 是白名单式，`video_model_durations` 不在返回字段里，导致 `canvas-config.json` 写入的时长范围被丢弃，前端永远拿到默认 `{min:1, max:60}`。
- **修复**：在 `normalizeProvider()` 返回对象补一行：
  ```js
  video_model_durations: raw.video_model_durations && typeof raw.video_model_durations === 'object' ? raw.video_model_durations : (existing.video_model_durations || {}),
  ```
- **验证**：node 实测 `getModuleConfig('canvas')` 返回的 apimart provider 已含 `video_model_durations`，seedance-2.5 = {min:2, max:30} ✅

### Bug #2（中）：切换模型后 duration 不越界同步

- **文件**：`resources/frontend/smart-canvas-core/smart-canvas-core.js`（`setDynamicSetting`）
- **根因**：切换模型时只重置了 `videoModel`，没有把 `videoDuration` clamp 到新模型范围，导致「Seedance 30s → 切 Veo」后生成时仍传 30s 给 Veo，API 报错。
- **修复**：`setDynamicSetting` 加分支：
  ```js
  if(key === 'videoModel'){
      const range = videoModelDurationRange();
      if(settings.videoDuration != null && settings.videoDuration !== ''){
          settings.videoDuration = Math.max(range.min, Math.min(range.max, Number(settings.videoDuration) || range.min));
      }
  }
  ```

### Bug #3（轻）：滑块实时数值显示失效

- **文件**：`resources/frontend/smart-canvas-core/smart-canvas-core.js`（`renderDynamicParams`）
- **根因**：滑块内联 `oninput` 被 `renderDynamicParams` 里 `input.oninput = ...` 覆盖，拖动时数值 span 不更新，只有松手才刷新。
- **修复**：把实时更新逻辑合并进 `renderDynamicParams` 的 oninput 绑定（按 `data-param === 'videoDuration'` 更新 `nextElementSibling`），并删除失效的内联 `oninput`。

## 验证

- 3 个文件 `node --check` 全通过
- Bug #1 用 node 脚本实测后端透传生效
- 已推送 GitHub（`121adf4`）

# 画布文字框滚轮滚动修复报告

## 问题
在普通画布、智能画布及复色画布中，鼠标悬停在 PROMPT 或其他文字输入框内滚动时，滚轮被画布根容器接管为缩放操作，文字框无法向下滚动查看内容。

## 根因
三套画布均在根容器绑定了 `wheel` 缩放逻辑，并调用 `preventDefault()`。

原有排除范围不完整：
- 普通画布只排除了 `textarea/input/select`，未覆盖 `contenteditable` 的提示词编辑器。
- 智能画布未把所有输入控件和 PROMPT 控件纳入缩放事件排除范围。
- 复色画布未在根级 `wheel` 处理前调用现有的 `isEditableTarget()` 判定。

因此，输入控件的原生滚动被父级缩放逻辑取消。

## 修复内容

### 1. 普通画布
文件：`D:\Lavans备份\resources\frontend\canvasStudio.js`

在画布缩放事件中补充 `[contenteditable="true"]` 判断。滚轮落在文本框、下拉框或可编辑提示词区域时，不再执行画布缩放。

### 2. 智能画布
文件：`D:\Lavans备份\resources\frontend\smart-canvas-core\smart-canvas-core.js`

在根容器缩放事件的排除范围中加入：
- `textarea`
- `input`
- `select`
- `[contenteditable="true"]`
- `.prompt-node-control`
- `.prompt-input`

滚轮在 PROMPT、LLM 指令、动态参数文本输入等区域时交还浏览器原生处理；空白画布区域仍可缩放。

### 3. 复色画布
文件：`D:\Lavans备份\resources\frontend\canvas.js`

根级 `wheel` 处理增加 `isEditableTarget(e.target)` 前置判断，直接复用既有的编辑控件识别逻辑，避免未来新增输入组件时再次遗漏。

## 验证

### 语法验证
执行：

```bash
node --check canvasStudio.js
node --check smart-canvas-core.js
node --check canvas.js
```

结果：三个文件均通过，退出码 `0`。

## 验收方式
1. 在三种画布中创建或打开含长文本的 PROMPT/文字节点。
2. 鼠标停在文字框内，向下滚动滚轮。
3. 预期：文字框内容向下滚动，画布比例不改变。
4. 鼠标移到画布空白处滚动。
5. 预期：画布仍按原行为缩放。

## 影响范围
- 仅修改前端滚轮事件路由。
- 未修改节点数据、提示词内容、画布缩放算法或后端服务。

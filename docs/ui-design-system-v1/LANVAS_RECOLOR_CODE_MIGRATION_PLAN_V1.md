## 1. 目标与硬边界

本次不是给旧页面换色，而是在保留 Lavans 全局外壳、共享 API 设置和既有可用能力的前提下，把一键复色整理成一套结构清楚、状态可信、结果安全的工作台。

必须遵守：

- 画布和一键复色共用全软件唯一 API 设置，不建立复色专用密钥或 Provider 配置。
- 复色的上传素材、任务、结果、历史和日志与画布隔离。
- 不做 Mask、圈选、自动 QC、自动纠色或自动连续重做；每次任务只向模型生成一次，由用户判断结果。
- 用户现有未提交修改必须保留；实施前逐文件建立恢复副本或取得 Git 恢复点授权。
- 深浅色共用一份结构，只切换主题令牌和材质强度。

## 1.1 执行模型调度（已确认方案 A）

Codex 是执行环境，SOL 与 Terra 是按任务风险选择的执行模型。后续固定采用“Terra 主力、SOL 攻坚”，不按文件数量或表面工作量判断。

| 执行区段 | 模型＋推理强度 | 范围 |
| --- | --- | --- |
| 实施前准备 | Terra＋中 | 读取文档、记录差异、建立文件级恢复副本、整理测试夹具；如果当前已经是 SOL，不为这一步单独降级。 |
| 阶段 A：状态真相 | SOL＋高 | 主状态、统计和状态测试；先保证任务记账正确。 |
| 阶段 B～C：费用与队列核心 | SOL＋第一个极高 | 一次调用、未知远端结果保护、原子保存、FIFO 队列、暂停恢复与追加；此处直接关系重复扣费和漏执行。 |
| 阶段 D：结果安全 | SOL＋高 | 重做、删除、历史和彻底清空边界；重点是旧图与其他模块数据不丢失。 |
| 阶段 E：明确功能 | Terra＋高 | 导出、裁剪、HEX 元数据和已导出标记。 |
| 阶段 F：视觉落地 | Terra＋中 | 已确认浅色/G 深色 UI、普通弹窗和文档同步。 |
| 阶段 G：整体验收 | Terra＋高 → SOL＋第一个极高 | Terra 先跑无付费回归并修正明确问题；进入最终跨模块安全审查前切换 SOL。 |

Codex 当前界面采用五档名称：`轻度`、`中`、`高`、第一个 `极高`、最下面带“更快消耗使用额度”提示的 `极高`。本计划中“第一个极高”只指上方的极高档；最下面的极高档称为“最高档”，默认禁止使用。只有 SOL＋第一个极高连续两次仍不能解释同一个核心安全问题时，Agent 才能建议最高档，且必须单独说明原因并等待用户明确同意。当前界面没有“无”档，不在本项目规则中使用。

强制换模提醒规则：

1. 只在稳定检查点切换模型，不在文件修改到一半时切换。
2. 需要调整模型或推理强度时，当前模型必须先停止下一阶段，不修改相关生产代码，并明确报告“下一步范围、建议模型＋推理强度、原因、当前检查点”。
3. SOL 攻坚区完成并通过记录后，必须停止并提醒切回 Terra；用户完成切换并回复继续后才进入下一执行区段。
4. Terra 执行中若发现跨模块状态冲突、重复扣费风险、删除越界、恢复不确定或既有测试无法解释，立即保存检查点并建议升级 SOL；SOL 已为高时需要升级到第一个极高也适用同一暂停规则，不允许硬做。
5. 普通小问题、机械修改和重复验证不触发换模，避免频繁中断。
6. 当前 Codex 套餐对不同模型的实际额度换算没有在项目内建立可靠数据，因此不承诺 SOL 与 Terra 的精确消耗倍数；模型选择只依据任务风险与返工成本。
7. 模型和推理强度的提醒使用用户可见的中文界面名称，例如“SOL＋第一个极高”，不只写内部英文档位，防止两个“极高”产生歧义。

## 3. 当前最重要的冲突

### P0：实施 UI 前必须修复

1. **状态统计错误**：`batchStore.js` 当前每个可见任务都会增加 `done`，等待和运行任务也会被算入完成。
2. **运行中追加漏执行**：`taskRunner.js` 只更新已存在任务的状态，没有把磁盘新增任务合并进 runner 的任务数组。
3. **重做先丢旧图**：`server.js` 在新结果成功前删除旧输出；新调用失败时用户会失去原图。
4. **一次生成规则未落实**：`taskService.js` 仍执行多轮纠正、QC 和 Mask 流程，和最终规格直接冲突。
5. **费用与未知结果不安全**：`apiClient.js` 会自动网络重试，但无法可靠区分“服务商未收到”和“已收到但本地没拿到响应”。
6. **队列保护实际失效**：生成入口读取旧 `status` 字段，并调用当前存储模块没有导出的 `loadAllBatches()`，异常被吞后按 0 处理。
7. **彻底清空越界风险**：前端清空后执行浏览器全局存储清空，可能伤及全局主题或其他模块状态。

### P1：与第一版可用体验同时完成

- 上传批次与执行批次分离。
- 提示词、模型、尺寸、质量、单价在提交时形成任务快照；密钥与地址提交时读取最新全局配置。
- 默认并发 8、范围 3～8；暂停只停止领取新任务，已提交任务继续收尾。
- 系统性错误熔断、免费健康检查、自动与手动恢复。
- 5 秒删除撤销、晚到结果丢弃、重做成功后原子替换。
- 历史结果使用复色独立索引，并和当前任务引用同一份结果文件。
- 导出组合筛选、语义化命名、冻结快照和结果版本“已导出”标记。

### P2：视觉整合和长期维护

- 8 个内层真实快捷图标。
- 完整浅色/G 深色主题、统一弹窗、三图全屏对比和真实裁剪编辑器。
- 将复色逻辑从巨型 `app.js` 分离为有限的状态、界面和接口模块；只在功能稳定后进行，避免边改逻辑边大拆文件。
- 增加复色专用自动测试，覆盖状态、费用、追加、暂停、重做、删除、恢复、导出和数据隔离。

## 5. 分阶段实施顺序

每一阶段最多集中修改 2～4 个核心文件，完成验证后再进入下一阶段。

### 阶段 A：状态真相与测试骨架

核心文件：`batchStore.js`、`server.js` 中追加任务的快照写入点、新增复色状态测试。

- 建立唯一主状态和运行标记。
- 修正 totals，只把已生成、失败和已删除等终态按规则统计。
- 加入上传批次、执行批次、模型/提示词/单价快照、结果版本、导出和删除字段的向后兼容默认值。
- 先写不调用真实 API 的状态与迁移测试。

通过标准：旧批次可读取；等待/运行不再计入完成；测试能构造并验证全部状态。

实施结果（2026-08-22）：已完成。

- `batchStore.js` 已增加 `mainStatus` 主状态、`runtimeStatus` 运行标记和版本 3 向后兼容迁移；旧 `executionStatus` 暂作为后续阶段迁移前的执行器兼容输入，统计不再读取它作为最终真相。
- `done` 只统计已生成与生成失败；等待、生成中和远端结果未知不再计入完成，正式删除后任务总数与费用统计归零，不恢复旧统计。
- 已补齐上传批次、执行批次、模型、提示词、尺寸、质量、锁定单价、结果版本、导出和删除字段默认值；运行中追加任务会在创建时写入本次设置快照。
- 新增 `resources/backend/tests/recolor-batch-store.test.js`，3 项复色状态测试通过；后端全部 90 项本地测试通过，未启动真实服务或调用 API。

### 阶段 B：一次调用、费用保护与结果原子保存

核心文件：`taskService.js`、`apiClient.js`、对应测试。

- 删除自动 QC/纠正/Mask 对任务结果的控制。
- 一次任务只提交一次模型生成；网络层记录每次真实尝试。
- 远端结果未知时暂停，不自动二次提交。
- 图片先写临时文件、验证可读，再原子替换正式结果。

通过标准：无真实 API 的模拟测试证明成功、普通失败、未知结果、落盘失败和费用记录都正确。

实施结果（2026-08-22）：已完成。

- `taskService.js` 已收敛为一次任务只执行一次模型生成；任务链不再调用自动 Vision、Mask、QC 或纠正轮次，成功后保留 `review_required` 交由用户判断。
- `apiClient.js` 已取消生成 POST 自动重试；生成前通过回调先持久记录一次真实提交和锁定单价。HTTP 4xx 作为明确失败，HTTP 5xx、提交后断网或超时作为远端结果未知；APIMart 保存 `task_id`，轮询失败不再重新创建远端任务。结果 URL 的 GET 下载重试保留，因为它不会再次触发生图费用。
- 远端结果未知时任务进入 `interrupted + remote_unknown`，批次设置安全暂停信号；runner 只等待已提交任务收尾，不再领取新任务。生成、追加、继续和单项重做入口均拒绝把该任务重新提交。
- API 次数和费用改为累计账本：请求发出前的本地失败计 0；每次真实生成提交计 1；普通失败、远端未知、下载或磁盘失败均保留已经发生的调用和费用，继续或人工重做不再清零历史。
- 图片先写同批次临时文件，经 Sharp 转码并完整像素解码确认可读后，再同目录原子改名为正式结果；任一步失败都清理临时文件且不删除旧正式结果。
- 新增 `resources/backend/tests/recolor-stage-b.test.js`，7 项阶段 B 模拟测试通过；后端全部 97 项本地测试通过。测试未启动真实服务、未连接 Provider、未调用付费 API。
- 修改前恢复副本位于 `D:\Lavans备份\backup_before_recolor_stageB_20260822_121435\`。
- 当前停在稳定检查点；阶段 C 继续使用 SOL＋第一个极高，不需要切换模型，但不得提前进入阶段 D 或 UI。

### 阶段 C：唯一 FIFO 队列、追加、暂停和恢复

# Lavans 全软件改色迁移经验 V1

更新时间：2026-08-24  
来源：一键复色主界面、浅深主题、14 个正式场景、跨 iframe 弹窗和无付费安全回归的完整改造。

## 1. 这次真正完成了什么

一键复色不是一次“换肤”，而是把已确认效果图中的版面、尺寸、材质、状态和交互逐项绑定到正式 DOM 与原有功能。最终保留了上传、裁剪、取色、手动 HEX、队列、暂停／恢复、历史、下载、费用、重做、清空、模型改绑、API 和画布隔离，同时让浅色与 G 近黑灰深色在软件 100% 下使用同一结构。

这套经验的价值不是复制一键复色页面，而是给后续每个独立页面提供同一套迁移方法：各页必须使用自己的确认效果图、DOM 和业务事件，只共享设计系统、验收纪律与安全边界。

## 2. 最有效的总流程

### 2.1 先冻结三层真相

每个页面开始前先固定：

1. **视觉真相**：用户确认的效果图优先，HTML 母版用于读取结构和尺寸，旧生产页面只提供业务能力。
2. **状态真相**：状态真相表说明当前到底完成、待验收还是被阻断；自动测试不能替用户宣布视觉通过。
3. **功能真相**：正式 DOM 的事件、接口、数据来源和失败路径必须从代码核对，不从效果图猜测。

效果图与说明冲突时，先回到已确认优先级；不能凭“看起来合理”自行补设计。

### 2.2 修改前建立映射

每个可见区都先写成一行：

| 母版／效果图元素 | 正式 DOM | 功能事件与数据 | 验收证据 |
| --- | --- | --- | --- |
| 上传卡 | 正式模板图／参考色卡 | 点击、拖放、粘贴、继续添加、移除、裁剪 | 实际软件截图＋交互专项 |
| 任务行 | 分组标题、模板图、生成图、任务元数据、状态、操作 | 筛选、选择预览、重做、删除、历史 | 列表回归＋截图 |
| 结果对比栏 | 双图与拖动线、参考色信息 | 选中任务、左右切换、折叠 | 比例检查＋事件回归 |
| 任务日志 | 标题、图标、筛选、日志行 | 清空、刷新、按级别筛选 | 图标／字号／行高对照 |
| 弹窗 | 场景专属面板 | 打开、取消、确认、Escape、焦点恢复 | 正式入口＋浅深截图 |

只有映射完成后才允许修改。这样能避免两类常见错误：视觉改对但事件丢失，或功能能用但仍是旧 DOM 近似换肤。

## 3. 样式架构：令牌、组件、页面分开

当前正式外壳加载顺序是：

```text
lanvas-tokens.css → lanvas-components.css → lanvas-shell-v3.css
```

一键复色页面再由 `lanvas-recolor-v3.css` 管理自己的工作台与 14 场景。旧 `lanvas-unified.css` 不再接入生产入口。

- **Tokens**：颜色、文字、边框、圆角、阴影、间距等语义值。
- **Components**：按钮、胶囊、卡片、输入框等跨页组件规则。
- **Shell**：Logo、顶栏、左栏、舞台和全局深浅材质。
- **Page**：某一独立页面的真实布局和业务状态，不反向污染其他页。

经验：不要在旧 CSS 尾部继续堆覆盖补丁。补丁多到无法判断权威值时，应建立最后加载且作用域清楚的正式层，再逐项迁移。

## 4. 浅深改色的核心规则

### 4.1 浅深主题必须结构同构

同一场景的 DOM、尺寸、字号、行高、图标、间距和按钮位置完全相同，只替换主题材质。不要为深色复制另一套业务 DOM，否则后续交互会分叉。

### 4.2 深色不是黑紫蒙层

- 页面、顶栏、左侧折叠栏、主工作区和右栏以接近黑色的中性灰为底。
- 紫色只用于品牌、选中、焦点、主要行动和少量状态强调。
- 禁止大面积紫底或“紫底＋紫字”；文字对比度必须在实际软件截图中可读。
- 选中态可使用紫色渐变或流光，但不能把普通容器全部染紫。

### 4.3 浅色也不能靠白色堆层级

浅色通过淡紫材质、细边框、轻分区和间距建立层级。模板图与参考色上传卡默认使用相同淡紫材质；点击、焦点或切换粘贴目标不能改变卡片底色和虚线颜色。

## 5. 尺寸与软件比例：满屏不等于放大

这次最关键的根因之一是软件壳对 iframe 做整体缩放，导致网页 100% 正常、软件里却字大、图标大、布局拥挤，或在 4K 上缩成中央小块。

最终原则：

- 软件壳始终铺满物理可见窗口。
- 所有内嵌页面保持 100% 组件密度，不用整页 `transform: scale()` 解决适配。
- 宽度变化使用真实响应式布局：折叠右栏、收纳次要动作、调整列宽；不缩小文字和图标。
- 用户日常 2560×1440 是主要验收窗口；1920×1080、1440×900、1280 宽用于响应式防回归。
- Windows 桌面缩放、软件缩放和浏览器缩放必须分别识别；最终视觉以用户实际软件 100% 为准。

以后遇到“网页对、软件错”，先测父窗、iframe、CSS 像素、设备像素比和是否存在二次缩放，不先改页面字号。

## 6. 弹窗：必须相对完整软件窗口居中

一键复色运行在 iframe 内，单纯 `position: fixed; inset: 0` 只能相对 iframe 居中，不等于完整软件窗口居中。

最终方法：

1. 子页读取真实弹窗面板矩形，而不是假设面板中心等于 iframe 中心。
2. 把真实面板中心映射到父窗口可见中心，计算动态补偿。
3. 窗口变化后重新测量，并保留最小可见边界，避免小窗口裁切。
4. 父窗遮罩连续覆盖标题栏、左栏、舞台间距和外框；活动 iframe 位于遮罩之上，弹窗保持可操作。
5. 浅深主题共用几何与事件；默认安全焦点、取消、关闭、Escape 和焦点恢复不能因视觉修复改变。

固定像素偏移只会在一个窗口看似正确，不能作为正式方案。

## 7. 一键复色的关键业务经验

### 7.1 生成中必须表达“不确定”

只显示“生成中”紫色状态胶囊、活动图标和无确定性的循环流光；不显示“正在调用模型”、百分比或其他伪确定进度。

### 7.2 费用入口必须来自同一真相源

顶部批次费用入口是整块可点击的两层结构：第一行“¥金额 · N 次 API 调用”，第二行“查看任务执行汇总”，右侧展开箭头。任务汇总、单价、调用次数和小计必须读取同一批次数据，不能用 UI 文案推算。

### 7.3 参考 HEX 是本地元数据，不是生成指令

- `referenceHex` 只用于列表显示、颜色命名、筛选、历史和导出打包。
- 已有任务从同批参考色元数据回填真实 HEX。
- 缺失时显示中性色块并明确“未设置色号”，不能伪装成正确灰色。
- 用户可手动修改 HEX 与颜色名。
- HEX 永不发送生成 API、不写入提示词、不参与 QC；这条隔离必须用专项测试保护。

### 7.4 图片比例必须诚实

模板图、生成图、参考图和右侧缩略图保持各自真实比例与约定画框；需要 1:1 的缩略图区必须固定为 1:1 容器并用合适的 `object-fit`，不能拉伸素材。全屏三图分别展示模板图、生成图和参考图，不把局部裁剪伪装成完整图。

### 7.5 暂停与模型改绑必须保持安全

- 用户暂停、系统 API 故障、远端结果未知是三种不同状态，文案和允许操作不得互相伪装。
- 暂停期间新增或重做只入 FIFO 队尾，不自动恢复、不增加调用和费用。
- 远端未知不自动重发。
- 模型改绑只允许零调用、零费用、未领取、未提交的 pending 任务；预览后发生竞态则整批 409。
- 确认接口必须有一次性预览令牌、请求幂等和保存失败回滚；成功后仍保持暂停，不启动 Runner 或 Provider。

## 8. 视觉与功能的双验收

### 自动验收负责什么

- 正式 DOM 和样式链存在。
- 点击、拖放、粘贴、裁剪、历史、导出、筛选、重做、删除和折叠事件仍然绑定。
- FIFO、恢复、远端未知、费用、模型快照和参考 HEX 隔离不回退。
- Provider 生成调用数、新增费用和真实写入为 0。

### 人工视觉验收负责什么

- 软件 100% 同一实际窗口与效果图并排对照。
- 逐区检查版面位置、区域高度、按钮、预览图、任务日志、图标、字号、行高、间距、材质、遮罩和焦点。
- 浅深两套都要检查，任务列表必须放入真实结构的本地夹具任务，不能只看空态。
- 自动测试通过后仍停在截图证据阶段，等待用户明确确认。

## 9. 失败过的方法与原因

1. **近似换肤**：保留旧 DOM 只改颜色，导致区域高度、按钮、日志和弹窗结构持续偏差。
2. **整页缩放**：网页比例正确但软件里拥挤或缩成小窗，且所有页面表现不一致。
3. **固定弹窗偏移**：只在单一分辨率下对齐，换窗口立即偏移。
4. **用 iframe 中心代替面板中心**：夹具几何看似通过，实际软件仍偏右下。
5. **遮罩只盖标题栏和左栏**：舞台间距留下亮边，破坏完整弹窗层级。
6. **紫色滥用**：深色页面变成黑紫蒙层，紫底紫字不可读。
7. **把自动测试当视觉完成**：测试全绿仍可能存在实际软件比例、字号和位置偏差。
8. **用旧文档覆盖代码真相**：例如测试仍要求已移除的统一样式层；正确做法是核对正式入口后修测试，不是恢复旧 CSS。

## 10. 其他独立页面的复制检查表

每迁移一个页面，按以下顺序执行并逐页等待用户确认：

- [ ] 找到该页已确认效果图与必要 HTML 母版，不借用一键复色业务布局。
- [ ] 建立“效果图元素 → 正式 DOM → 功能事件 → 数据来源 → 验收证据”映射。
- [ ] 列出必须保留的功能、名称、描述、导航顺序、API 和数据边界。
- [ ] 识别该页样式作用域，先用 Tokens／Components／Shell，页面独有规则放入页面层。
- [ ] 保证浅深主题 DOM 同构；深色以 G 近黑灰为底，紫色限于品牌、选择、焦点和主行动。
- [ ] 取消整页缩放，软件满屏且页面保持 100% 组件密度。
- [ ] 核对上传、列表、预览、日志、底栏、空态、错误态和弹窗，不只检查首页静态状态。
- [ ] 弹窗按完整软件窗口居中，遮罩覆盖完整父窗，焦点和 Escape 安全。
- [ ] 使用本地夹具或伪 Provider 验证，不调用真实／付费 API，不上传真实素材。
- [ ] 先跑语法和专项，再跑相关全量回归；记录真实通过／失败数量。
- [ ] 在用户实际软件 100% 同一窗口生成浅深并排证据，自动通过后仍等待人工确认。
- [ ] 每个独立步骤更新外置大脑、状态真相表和交接事件日志，只保留一个推荐下一步。

```text

功能真相：正式 DOM、事件、接口和数据来源
必须保留：功能、名称、顺序、数据与安全边界
禁止：近似换肤、整页缩放、真实 API／素材、范围外重构
允许修改：明确到文件和页面作用域
浅深规则：同构 DOM、G 近黑灰、紫色使用边界
测试：语法、专项、回归、零调用／零费用断言
视觉验收：实际软件 100%，同一窗口并排逐区测量
恢复：修改前备份路径

状态：未开始／执行中／待人工审核／已验收
唯一下一步：只写一项
```

## 12. 收口原则

达到效果图 1:1、功能不退化、安全回归通过并获得用户实际软件确认后，立即停止该页改造。不要以“统一”为名继续重构其他页面；下一页重新建立自己的映射和验收证据。

## 2. 全软件不可变边界

- 只重做 UI；保留全部现有功能、名称、描述、顺序、路由、数据、业务逻辑、快捷键和操作路径。
- 品牌可见名称统一为 `Lavans`；不再显示 `Lavans` 或 `Lavans` 产品字样。
- 全软件共用 MiSans VF、JetBrains Mono 日志字体、Phosphor Duotone 图标和 Lavans 主题令牌。
- 深浅模式使用同一 DOM、中文文字、图标、字号、尺寸和位置，只切换颜色、材质、阴影与可读性令牌。
- 全局左侧栏属于整个软件，名称、顺序、入口、折叠方式与功能保持不变；系统功能组按已确认位置下移。
- 左侧栏底部固定短文案“改自大雄画布，致敬原作”，整行链接 `https://github.com/hero8152/Infinite-Canvas`。
- API 设置是全软件唯一配置入口；其现有版块、字段、顺序、位置、按钮和条件显示不得重构。
- 一键复色和画布是独立系统，不共享素材、模板、任务、项目或生成记录；只共同读取全局 API 配置和全局主题状态。
- 统一 API 的含义已经用户再次确认：画布 API 设置完成后，一键复色直接使用同一套 Provider、模型列表、密钥和调用能力；不得建立复色独立 API 设置、独立 Provider 存储或第二份密钥。
- 当前脏工作区全部视为用户资产；不得重置、清理、覆盖、暂存、提交、推送或发布，除非用户另行授权。
- 若实现需要功能性或大范围结构改造，立即暂停并说明影响。

## 3. 版面规则与唯一例外

### 3.1 默认规则

除一键复色的已批准范围外，所有页面保持当前生产版面：区域位置、宽高关系、列宽、按钮位置、弹窗、滚动、折叠、响应式断点和交互路径不变。允许替换的只有视觉皮肤和不改变几何尺寸的图标。

### 3.2 一键复色例外

一键复色保留“全局导航之外的内层工具栏 + 中间任务主区 + 右侧检查栏”大结构和全部业务能力，但允许为精确还原已确认效果调整其内部尺寸、留白、行高、缩略图、任务工具栏、统计区和右侧面板比例。

一键复色的精确还原以 `D:\Backup\Documents\temu\lanvas-design-system-v1\lanvas-ui-master.html` 为唯一版面判定依据。按钮大小和所有区域之间的位置、尺寸与比例关系均属于验收项。

一键复色必须同时满足：

- 中间任务区占可用主工作区约 70–80%，任务连续滚动，不分页。
- 列表和右栏都只显示“模板图 → 生成图”两张图片；右栏不显示参考色图、自动质检或色差判断。
- 每项任务的操作栏只保留“重做”和“删除”两个图标按钮；点击缩略图在右栏预览，下载放在批量/导出区域。
- 失败原因与失败任务保持同一行；右栏不显示自动质检状态或色差结论。
- 任务状态固定为“等待生成、生成中、已生成、生成失败、已删除”；不设置“确认通过”，已生成只表示 API 正常返回图片，不代表系统判断颜色正确。
- 一键复色不提供圈选或 Mask。正式生成只采用整图自然复色，禁止把圈内生成结果与圈外原图硬拼接；用户通过模板图和生成图双图对比自行检查背景、文字、结构、光影、纹理和颜色。
- 用户查看对比图后自行判断色差。用户点击一次“重做”时，将整张模板图和该任务实际参考图交给任务创建时绑定的 API 模型生成一次；生成后停止。每项任务只保留一张最新成功结果：新图成功后替换并删除旧图，重做失败则保留旧图。不允许自动连续重做、本地调色、修图或硬拼接。
- 点击重做必须先弹费用确认框，显示任务缩略图、当前模型和“将产生 1 次新的 API 调用”；只有点击“确认重做”才执行，默认焦点在“取消”，关闭或按 Esc 不调用 API。
- 重做确认框必须作为正式页面组件重新设计，不使用浏览器默认确认框，也不在旧弹窗上简单换色。弹窗遵循“紫域工作台”、Phosphor 图标、统一字体/圆角/间距和深浅色同构规则。
- 弹窗信息顺序固定为：标题“确认重新生成”→ 当前任务缩略图 → 当前模型 → 1 次 API 调用提示 → 新图成功后替换旧图的说明 → 取消/确认重做按钮。确认重做是弹窗内唯一主按钮。
- 首次批量生成使用正式确认弹窗，显示任务数、当前模型、并发数和预计调用次数；单任务重做使用独立费用确认弹窗。
- 全局 API 错误必须一次触发立即暂停整批，包括密钥失效、余额不足、模型不可用和接口地址错误；普通单任务内容或生成失败只影响当前任务，不暂停其他任务。
- API 恢复后系统优先自动继续，同时保留“继续生成”按钮。两种恢复方式都先执行非生成型可用性检查；不得用付费图片生成充当健康检测。
- 生成过程中新增图片产生的任务自动加入当前队列继续执行，无需再次点击开始生成；用户主动重复上传同一素材也创建独立任务。执行器按任务编号保证幂等，统计即时更新，暂停期间只入队不执行。
- 配对采用模板优先全组合：模板图 1 × 全部参考色，然后模板图 2 × 全部参考色，再到后续模板。所有任务放在同一个连续列表中，使用轻量、短暂吸顶的模板分组标题，不增加折叠区或独立分组列表。
- 运行中新增参考色产生的补充任务统一追加到连续列表末尾，不插入旧任务之间；追加部分内部按模板顺序排列，已有行不得移动。
- 顶部统计固定为“任务总数、已生成、生成中、失败”，删除“成功率”；已生成只表示 API 正常返回图片，正式删除的任务不再计入总数。
- 点击任务后右栏锁定该任务，其他结果完成不得自动切走；未手动选择时显示最新生成结果。点击图片可放大。
- 底部固定操作栏只有开始生成、导出结果、彻底清空三个按钮；不得放清除已生成、清除失败或其他按钮。
- 任务列表快捷筛选固定为全部、已生成、生成中、失败，连续滚动、不分页。
- 右侧日志默认显示最近记录，错误红色标记并置顶，保留清空日志。
- 彻底清空取代原“重置”，删除一键复色内部全部数据：上传素材、任务、配对记录、生成结果、缓存、临时文件和日志；必须使用重新设计的不可撤销危险确认弹窗，不得触碰画布数据、全局 API 设置或全局主题。
- 运行中确认彻底清空后，先停止本地队列、尝试取消远端任务，再清理数据；取消不了时提示可能仍产生费用并丢弃迟到结果。
- [已被第 53 项覆盖] 曾要求导出入口直接导出全部；现行规则为弹窗默认全部，并允许用户主动按条件导出，主任务筛选仍不影响导出。
- 右栏双图采用同一画框中的可拖动对比线，点击可放大。
- 顶部上传区使用模板图、参考色两个大面积拖拽框，平分主宽度且整卡可点击/拖拽；普通添加后自动配对并创建任务，裁剪后添加则在确认裁剪预览后创建任务，不显示扫描配对按钮。
- 任务行取消复选框，只保留编号、模板图到生成图、状态/进度、重做和删除。
- 右栏上半部为双图对比，下半部为日志；可折叠，恢复后保留锁定任务。
- 彻底清空弹窗必须按紫域工作台重新设计，显示完整删除范围、不可撤销和可能产生远端费用；默认焦点取消，不要求输入文字。
- 导出 ZIP 与包内图片使用日期、模板名、参考色名和生成时间构成可读文件名，不采用 01、02 等纯序号；同名时才追加 4 位短识别码。
- 底部生成主按钮在同一位置按状态切换为开始生成、暂停生成、继续生成。
- 生成过程中允许导出；只打包导出时已经完成的全部最新结果，未完成任务继续运行。
- 上传区已选状态显示第一张缩略图、文件总数、继续添加和移除全部，并保留较大的拖拽命中区。
- 完全相同的模板图和参考色允许重复上传并主动创建重复组合任务，不提示“已存在”。每次主动创建分配独立任务编号；后台只按任务编号防止同一任务因刷新、恢复或重复领取而重复调用。
- 删除按钮在等待、生成中和已生成阶段均可立即使用。点击后任务立即从界面隐藏并进入 5 秒待删除期；超时后再从本地队列移除并尝试取消远端调用。远端无法取消时提示可能仍产生费用，并丢弃迟到结果，任务不得重新出现。
- 删除不弹确认框：点击后任务立即从列表隐藏，底部显示 5 秒“撤销”；超时后才永久删除并尝试取消远端任务，撤销则恢复删除前状态。
- 保留模板图、参考色上传、自动配对、生成、筛选、日志清空/刷新、局部重做、双图详情和键盘左右切换；扫描配对已由自动创建任务取代，重置已由彻底清空取代，无用途的任务复选框与批量勾选移除。
- 仅删除复色内部独立深浅模式按钮；原“重置”由底部“彻底清空”取代，不得增加复色内部 API 设置。

## 4. 视觉规则

- 浅色大面积使用白色和冷中性浅灰；禁止大面积黑色、米黄和纸张黄。
- 深色不使用纯黑；正文和按钮文字必须达到清晰可读的对比度。
- 深紫是品牌强调色；主操作使用紫色斜向光带玻璃按钮，不能退化为平面紫色。
- 绿色、琥珀色、红色只表达完成、等待/警告、失败/危险，不作为装饰品牌色。
- 每个区域最多一个主按钮；次级操作保持克制，危险操作二次确认。
- 不通过缩小或压窄中文字体解决空间问题。

## 5. Agent 与视频系统

- 画布 Agent 保留现有 Skill 卡片、资料上传、勾选式问询、可见节点、状态灯、暂停/恢复、审核门、局部重做和版本产物。
- 能勾选的问题使用选项卡；只有“其他”允许输入。
- 不提供跳过剧本、分镜、旁白、逐镜视频审核的“一键成片”。
- 视频系统继承 Lavans 统一字体、图标、深浅主题和紫色光带主按钮，不建立橙色独立主题。
- 图片和视频模型继续读取全局 API 设置；失败时保留素材、提示词、成功产物和历史版本，支持提示词联动修改与单镜头重做。

## 6. 效果图、实现和验收

- 已确认效果图继续作为视觉参照；不再把“每次改动都必须重新出图”作为开发前置条件。
- 用户要求效果图或出现高风险视觉分歧时，才更新对应浅色/深色效果图；两种主题必须同构。
- 日常开发以真实软件浏览器截图、DOM/尺寸检查和交互测试作为主要验收证据。
- 每个阶段执行“开发 → AI 测试 → 范围内问题立即修复 → 用户审核”。
- 阶段结束前同步需求、架构、进度、测试和恢复记录。

## 7. 本次冲突裁决

1. “所有页面绝对零版面变化”修正为“默认零版面变化，一键复色按已批准范围精确还原”。
2. 文生图“模型和尺寸改为选择卡”撤销；保留当前控件形态与位置，只做视觉统一。
3. 工作流设置的假定固定宽度撤销；保持当前生产页面几何结构。
4. “每次修改必须重新导出效果图”改为按用户要求或重大视觉分歧触发。
5. 设计系统负责视觉令牌，页面规范负责页面应用，需求负责产品边界；不再互相争夺“唯一规范”地位。
6. 效果图不得删除上传、日志、任务操作等未被新决定覆盖的真实功能，也不得创造生产中不存在的功能；原重置已由彻底清空取代。
7. “复色独立 API 设置”提议撤销；继续使用全软件唯一 API 设置，复色只隔离业务数据、任务、队列、结果和日志。
8. 不设置逐任务“确认通过”；生成完成后直接显示“已生成”，其含义仅为 API 已返回结果，不等于系统判断复色质量合格。
9. “圈选/Mask 作为默认或备用保护”提议撤销；正式产品不提供圈选，采用整图自然复色与用户双图检查，禁止硬边拼接。
10. 色差由用户判断，不由系统判断；用户点击一次重做，该任务创建时绑定的 API 模型只生成一次，然后停止。本地系统不修改图片像素，也不自动连续重做。本条模型含义由第 34 项明确。
11. 任务行只保留“重做”和“删除”按钮；删除可在生成过程中即时执行，已删除任务不得因远端迟到结果而恢复。
12. 删除保护采用 5 秒短时撤销，不使用打断批量工作的确认弹窗。
13. 一键复色不提供历史版本切换；每项任务只保留最新一张成功结果。重做成功后删除旧结果，重做失败时保留旧结果，避免结果丢失。
14. 重做属于付费操作，必须二次确认；不得因误点图标直接发起 API 调用。
15. 重做确认弹窗属于一键复色母版 UI 的正式组成部分，必须随页面一起重新设计并接受深浅色视觉验收。
16. [已被第 32 项覆盖] 曾决定首次批量生成不二次确认；现行规则改为正式生成确认弹窗。
17. 系统性 API 错误立即熔断整批，不采用“连续失败若干次后再暂停”；单图错误不得误伤整批。
18. 熔断恢复采用“自动恢复优先、手动继续兜底”；检测通过前不得恢复队列，也不得产生图片生成费用。
19. 运行队列支持实时追加；新增任务必须被同一执行器确认领取，禁止出现“界面已有任务但后台未执行”。
20. 全组合任务进入同一个连续列表，并按模板优先顺序稳定排列；即使结果并发返回，任务位置也不得变化。
21. 运行中新增参考色的任务只追加到列表末尾，禁止为了维持初始全组合顺序而重排已有任务。
22. 顶部统计不展示成功率，避免被误解为颜色质量合格率；改为任务总数、已生成、生成中、失败。
23. 右栏采用模板图与生成图双图预览，锁定用户选择；参考色不占右栏图片位置。
24. 底部固定操作栏精简为开始生成、导出结果、彻底清空三个按钮。
25. 任务筛选固定为全部、已生成、生成中、失败；日志错误置顶并保留清空。
26. 彻底清空删除一键复色全部内部数据并取代重置；运行中先停队列和取消远端，再清理，不可撤销。

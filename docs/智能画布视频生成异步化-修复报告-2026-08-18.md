## 二、本轮核心改造：异步化（Init-Step-Poll）

### 2.1 后端 `canvasRoutes.js`

- 拆出 `queryApimartVideoOnce()`：单次查询上游任务，返回 `succeeded / running / failed` 三种状态。
- 拆出 `localizeVideoUrls()`：把上游视频 URL 下载到本地 `/canvas-output/`。
- `POST /api/canvas-video`：提交任务后**立即返回** `{ task_id, provider_id, status: 'submitted' }`，不再同步等待。
- 新增 `GET /api/canvas-video/:taskId`：单次轮询，成功则下载视频返回 `{ status:'succeeded', videos:[...] }`，失败返回 `{ status:'failed', error }`，否则 `{ status:'running' }`。

### 2.2 前端 `smart-canvas-core.js`

- `runApiVideoGeneration()` 提交后若返回 `task_id`，调用新增 `pollCanvasVideo(providerId, taskId)`。
- `pollCanvasVideo`：每 5 秒轮询一次，最长 30 分钟，成功后返回本地视频 URL，失败则抛出上游真实错误。

- 内容政策拦截时，上游真实失败原因能正确透传到前端（不再是笼统超时/失败）。

### 关键发现：模型分辨率枚举差异

实测发现两个模型不支持 480p，已确认 `canvas-config.json` 的 `video_model_resolutions` 配置正确固化，前端按模型展示正确选项：

| 模型 | 分辨率枚举 |
|------|-----------|
| flux-3-video | hd / fhd |
| kling-3.0-turbo | 720p / 1080p |
| 其余 5 个模型 | 480p / 720p / 1080p（默认） |

运行态 `GET /api/canvas/config` 已验证正确返回该配置。

## 五、已知限制与剩余风险

1. **轮询接口幂等性欠缺**：任务 `succeeded` 后重复调用轮询接口会重复下载视频（前端只轮询到第一次 succeeded 就停止，正常不会触发；仅手动多次调用可见）。
2. **密钥安全**：此前曾在工具命令中暴露过 APIMART Bearer Key；用户已确认是私人电脑、暂不轮换。

## 六、结论

三个问题（60 秒滑块、`/v1/v1` URL、同步阻塞超时）均已修复并完成真实运行态验证。7 个视频模型全部以最少秒数 + 最小分辨率实测通过，模型分辨率枚举差异已固化到配置并验证透传。视频生成链路已从「同步阻塞」改为「提交立即返回 → 前端轮询」，点击运行不再超时失败，能正确展示上游真实状态与结果。

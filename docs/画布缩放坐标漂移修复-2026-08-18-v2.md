# 画布缩放坐标漂移修复（第二版）

**日期**: 2026-08-18  
**文件**: `resources/frontend/smart-canvas-core/smart-canvas-core.js`（`editDrawPoint` 函数）  

---

## 问题

第一版把 `editDrawPoint` 改为纯 `getBoundingClientRect` 后，画笔/遮罩漂移反而更严重（偏移约 1.47 倍）。

## 根因

通过 agent-browser 查询发现：**本机 `studio-ui-scale=0.68`**（CSS `zoom` 不等于 1）。

```css
html[data-studio-scale="off"].studio-scale-managed .image-edit-modal {
    zoom: var(--studio-ui-scale, 1);  /* 本机 = 0.68 */
}
```

**坐标系冲突**：

| 值 | 来源 | 受 CSS zoom 影响？ |
|----|------|-------------------|
| `clientX` | 鼠标视口坐标 | 否（CSS 像素） |
| `getBoundingClientRect().width` | 元素视觉尺寸 | **是**（缩放后尺寸） |
| `offsetX` | 元素自身布局坐标 | 否 |
| `clientWidth` | 元素 CSS 布局宽度 | 否 |

`getBoundingClientRect` 公式：`(clientX - rect.left) * canvasWidth / rect.width`

- `clientX` 是 CSS 像素（未缩放），`rect.left` 是视觉像素（缩放后）
- 两个坐标系冲突，导致坐标被放大 `1/0.68 ≈ 1.47` 倍

**参考仓库为什么能工作**：参考仓库 `studio-ui-scale` 默认=1（不缩放），`getBoundingClientRect.width` = `clientWidth`，两个坐标系一致。

## 修复

还原为 `offsetX` 优先路径：

```js
function editDrawPoint(event){
    const canvasEl = editDrawCanvas();
    const cw = Math.max(1, canvasEl.clientWidth);
    const ch = Math.max(1, canvasEl.clientHeight);
    // offsetX/offsetY 与 clientWidth 同属元素布局坐标空间，
    // 不受父级 CSS zoom（studio-ui-scale）影响。
    if(typeof event.offsetX === 'number' && typeof event.offsetY === 'number'){
        return {x:event.offsetX * canvasEl.width / cw, y:event.offsetY * canvasEl.height / ch};
    }
    const rect = canvasEl.getBoundingClientRect();
    return {x:(event.clientX - rect.left) * canvasEl.width / Math.max(1, rect.width), y:(event.clientY - rect.top) * canvasEl.height / Math.max(1, rect.height)};
}
```

**原理**：`offsetX` 和 `clientWidth` 同属元素 CSS 布局坐标空间，不受父级 CSS `zoom` 干扰。无论 `studio-ui-scale` 设为多少，坐标映射始终精准。

## 验证

- `node --check` 语法通过 ✅
- 本机 `studio-ui-scale=0.68` 环境，`offsetX/clientWidth` 同坐标系 ✅

## 教训

参考仓库的代码不一定直接适用——需要检查运行环境差异。本机 `studio-ui-scale` 非默认值导致参考方案的 `getBoundingClientRect` 失效。

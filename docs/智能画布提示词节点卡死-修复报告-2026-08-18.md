# 智能画布提示词节点卡死 - 修复报告

- 日期：2026-08-18
- 模块：智能画布（smart-canvas-core.js）
- 提交：`b2a1140`

## 一、症状

用户反馈：智能画布里「提示词节点」只要出现，整个画布就不正常——卡死、节点错乱、影响其它节点、连线有问题、拖拽点击无反应。

## 二、根因

`smart-canvas-core.js` 的 `bindPromptNodeControls()` 函数（提示词节点渲染后绑定事件）里，L9261 直接引用了 `systemEl`，但**漏了声明语句**：

```js
// 修复前（L9260-9261）
    };
    if(systemEl) { ... }   // ← systemEl 从未声明，抛 ReferenceError
```

当提示词节点渲染后执行到这一行，浏览器抛出 `ReferenceError: systemEl is not defined`，导致：

1. `bindPromptNodeControls` 中断
2. 调用它的 `bindNodeEvents` 中断 → 后续所有节点的事件都没绑定 → **拖拽、点击、选中全部失灵**
3. 连线事件绑定也被波及 → **连线错乱/失效**
4. 渲染流程被异常打断 → **节点错乱、界面卡死**

## 三、对比大神仓库定位

对比大神仓库 `hero8152/Infinite-Canvas` 的 `static/js/smart-canvas.js`（L8713），大神的正确写法有声明：

```js
const systemEl = el.querySelector('.prompt-llm-system');
if(systemEl) { ... }
```

我们的版本漏了 `const systemEl = el.querySelector('.prompt-llm-system');` 这一行——是之前加「提示词全屏功能」时引入的疏漏。

## 四、系统对比结论（除全屏功能外）

逐函数对比大神 `smart-canvas.js` 与我们 `smart-canvas-core.js` 的提示词节点代码：

| 函数 | 结果 |
|------|------|
| promptNodeInputImages / promptNodeInputMediaForLLM / smartNodeInputThumbsHtml | 完全一致 |
| promptLlmInstructionHeight / promptNodeSeparator / promptNodePromptItems | 完全一致 |
| promptNodeSplitExtraHeight / promptNodeSplitPreviewHeight / syncPromptNodeHeightForSplit | 完全一致 |
| promptNodeMinHeight / promptNodeUpstreamPromptItems / promptNodeExpandedHeight / promptNodeLayoutSize | 完全一致 |
| promptNodeBodyHtml | 仅多「editor-wrap 包裹 + 放大按钮」（全屏功能，符合预期） |
| bindPromptNodeControls | **systemEl 漏声明（唯一 bug）** + 放大按钮（全屏功能） |

**结论**：唯一需要修复的差异就是 `systemEl` 漏声明，其余全部一致。

## 五、修复

在 `bindPromptNodeControls()` 里 `if(systemEl)` 之前补上声明（最小改动，仅 1 行）：

```js
const systemEl = el.querySelector('.prompt-llm-system');
```

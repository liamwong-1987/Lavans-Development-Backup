# 普通画布 Ctrl+Shift+Z 重做快捷键修复

**日期**：2026-08-19  
**范围**：普通画布（`resources/frontend/canvasStudio.js`）  
**未修改**：智能画布逻辑、撤销/重做数据结构、节点交互。

## 问题

普通画布中执行一次撤销后，`Ctrl+Shift+Z` 无法恢复上一步；智能画布相同快捷键正常。

## 根因

普通画布虽然在 `bindCanvasStudioShortcuts()` 中写了 `Ctrl+Shift+Z → canvasEditorRedo()`，但监听器注册在 `document` 的冒泡阶段。

外层页面同样存在全局 `Ctrl+Z` 监听。事件从目标节点向上冒泡时，普通画布快捷键可能已被外层监听消费，导致普通画布的 `canvasEditorRedo()` 没有收到调用。

普通画布自身的历史栈实现无异常：

- `canvasEditorUndo()`：从 `undoStack` 弹出快照并压入 `redoStack`
- `canvasEditorRedo()`：从 `redoStack` 弹出快照并压入 `undoStack`

故障点是快捷键路由层，不是历史快照层。

## 修复

在普通画布快捷键绑定函数中新增一个 `document` 捕获阶段监听：

- 仅当 `canvasStudioState.active === true`
- 且焦点不在 `input`、`textarea`、`select`、`contenteditable`
- 优先处理：
  - `Ctrl/Cmd + Z` → `canvasEditorUndo()`
  - `Ctrl/Cmd + Shift + Z` → `canvasEditorRedo()`
  - `Ctrl/Cmd + Y` → `canvasEditorRedo()`
- 调用 `preventDefault()` 和 `stopImmediatePropagation()`，避免外层全局快捷键再次截获或重复执行。

原冒泡阶段的 Z/Y 分支已删除，避免同一功能双入口维护。

## 验证

- 语法验证：

```text
node --check D:/Lavans备份/resources/frontend/canvasStudio.js
Exit Code: 0
```

- 验收操作：
  1. 在普通画布新增、移动或删除一个节点；
  2. 按 `Ctrl+Z` 撤销；
  3. 按 `Ctrl+Shift+Z`，节点状态应恢复；
  4. 按 `Ctrl+Y`，也应恢复；
  5. 将光标置于节点文本框，快捷键应保留文本编辑器原生行为。

## 风险与边界

改动仅影响普通画布激活状态下、非编辑控件焦点中的撤销/重做快捷键；不影响智能画布和页面其它模块。
